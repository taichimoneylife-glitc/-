# トークリール自動編集の流れ（設計表＋デザイン規則＋確認）

やることは「解析 → 秒数の設計 → 作る → 確認 → 書き出し」。

## 1. 素材
- 正面のトーク動画（mp4/mov・縦）。台本があれば一緒に。ロゴや画面の画像を使うなら透過PNG。

## 2. 解析（作る前に必ず）
- 長さ・解像度・fps（`ffprobe`）
- 言葉ごとの秒（`scripts/transcribe.py` → public/words.json）
- 言い直し・長い無音（words.json の秒の空き）
- **顔・口元・手を避けて、文字・図解を置ける場所**（何コマか静止画を抜いて見る）
- iPhone の HDR は `scripts/prep_video.sh` でふつうの色に直す

## 3. 設計表（これを埋めてから作る）
| 開始s | 終了s | 話していること | 見せ方 | Remotionで作るもの |
|---|---|---|---|---|
| 0.0 | 2.4 | 〇〇で損したくないなら | 実写＋寄り | 字幕（「損」を強調）＋上にタイトル |
| 3.0 | 7.4 | やることは3つ | 実写＋上にパネル | steps（3枚のカード） |
| 10.4 | 14.2 | 10年でくらべると | **全画面の図解** | compare（A vs B） |
- 共感・気持ちを伝える所は**顔を見せる**（図解は控えめ）
- 手順は**カードと矢印**、大事な数字は**大きい数字＋カウントアップ**
- 時間配分の目安：全画面の図解 1 ： 顔 2

## 4. デザインの決まり
- 図解のパネル・全画面の図解：**白い紙＋青いノート線**・濃い文字・アクセント1〜2色。実写の上の字幕は「白の極太＋黒い縁」
- 字幕は2行以内。顔・口元・手に重ねない（上＝図解、下＝字幕）
- 上の見出しと下の字幕で、同じことを言いすぎない
- 動くものを増やしすぎない＝**視線の行き先は1つ**
- 寄り：ずっとゆっくり寄る＋大事な言葉でグッと寄って戻る（約0.4秒）
- 効果音：図解が出る時に u02s（ポン）、全画面への切り替えに u03s。声より小さく（使い分けは sfx.md）

## 5. 確認チェックリスト（書き出したMP4を通しで見る）
- [ ] 話と字幕の中身・タイミングが合う（数字・固有名詞のまちがいがない）
- [ ] 文字が小さすぎず、出ている間に読み終われる（2行以内）
- [ ] 顔・口元・手が、見せたい所で隠れていない
- [ ] 上の見出しと下の字幕が重なりすぎていない
- [ ] 動くものが多すぎず、どこを見ればいいか分かる
- [ ] 声が聞き取りやすく、効果音がじゃましない
- [ ] 最後に何をすればいいか（保存・コメントなど）が分かる
- [ ] 音切れ・黒い画面・素材の抜け・文字化けがない
- [ ] インスタの下のボタン・説明文（y 1400 より下、右はし）に大事なものがない

## 6. 直し方
- 「何秒の・どこを・どう変える」で1つずつ直す。直したら、その秒の静止画で確かめてから書き出す
