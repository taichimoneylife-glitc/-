# 図解リール 前提条件・決定台帳（DESIGN_RULES）

**目的：一度決めたことを二度と修正しないための台帳。**
新しい指摘・決定が出たら、ここに1行ずつ追記していく。動画を作るときは毎回この前提に従う。

> 使い方：修正指示が出る → 直す → **その決定をここに追記** → 次から自動で守る。
> 「毎回同じ指摘をする」をゼロにするための場所。

---

## 1. カラー（`src/theme.ts` COLORS）

| 用途 | 色 |
| --- | --- |
| 背景 | `#F4EFF2`（薄いラベンダー） |
| メイン文字・線・枠（ink） | `#1B2A4A`（ネイビー） |
| アクセント（accent） | `#E5432B`（レッド）＝強調ワード・重要な線・数字 |
| グレー（補足文字） | `#6C7A93` |
| 白 | `#FFFFFF`（箱の地・帯の文字） |

- 赤は「一番効かせたい1語 / 重要な数字 / 結論への線」だけ。乱用しない。

---

## 2. レイアウト（絶対ルール）

- 要素は**固定スロット**に置く（毎回同じ位置）。バラバラにしない。上から順に：
  - 見出し(枠) → 箱(1〜2) → 結論(大) → 特大数字(赤) → 注記(グレー) → 帯(紺) → 締めの一文
- **見出しは1行**（枠は文字幅に合わせて自動で伸縮＝`inline-flex` + `nowrap`）。折り返させない。
- 箱のラベルも**折り返さない**（`nowrap`）。長い語は短くする（「総支払 約550万」→「総支払 550万」）。
- **改行は必ずキリのいい所で（最重要）**。単語やフレーズの途中で折り返さない
  （NG例：「保存＆フォロ／ー」「…できるのは債／券」）。長い帯・結論は
  `<br>` で意味の区切りに手動改行する。自動折り返しに任せない。
- **キーワードは大きく＆色替え**して目立たせる。例：帯を2行にして
  「10年後を"確定"できるのは →（改行）→ **債券**」を大きくゴールド(#F6C544)に。
  （紺地の帯の上ではゴールド／白、薄い背景の上では赤(accent)が映える）
- 1画面＝1メッセージ。ただし**情報密度は参考画像を下限**とする（スカスカ厳禁）。箱を線でつないで"組み上げ"を見せる。
- **一番下の端（下から約300px）には文字を置かない**。締めの一文もそのゾーンより上（画面の約71%＝y1360）に固定。
- **線と文字は絶対に重ねない**。結線は次の文字ブロックの手前で必ず止める（最低30px空ける）。
  - 見出しサブや箱サブの上を線が通らないよう、経路も文字を避ける。

## 3. 文字サイズ（`diagram.tsx`。参考画像を1080幅換算で実測して決定）

参考：産休・育休の連結図解を実測（1080幅換算のグリフ高→フォントサイズ換算）。

| 要素 | 参考画像の実測(px) | 採用サイズ(px) |
| --- | --- | --- |
| 見出し（枠内） | 約72 | **64** |
| 箱ラベル | 約58 | **50** |
| 箱サブ | — | 34 |
| 結論（大テキスト） | **約104** | **98**（74は小さすぎ→拡大） |
| 特大数字（赤） | 約95 | 100 |
| 注記（グレー） | 約36 | 34 |
| 帯（pill・紺地に白） | 約62 | **66**（58は小さすぎ→拡大） |
| 締めの一文（帯の下） | 約60 | 60 |

## 3-2. 1枚あたりの文字量（密度の下限）

- 参考画像（産休・育休）の**1枚 ≒ 約75文字**（見出し7＋サブ7＋箱4+4＋結論8＋数字8＋注記16＋帯12＋締め12）。
- **これを1ページの下限**とする。これより少ないとスカスカ＝NG。
- 足りないときは「箱を2つにする」「注記・帯・締めの一文を足す」で密度を上げる。

## 4. アニメーション

- **ページ切替＝下から上へスライド（`slide from-bottom`、"シュッ"）**。左右スライドは使わない。
- **線の描画はゆっくり**（参考動画のカデンス＝体感0.5秒間隔＋所々のタメ）。速すぎ厳禁。
  - `diagram.tsx` の `draw()` 開始/長さと、各要素の出現 `delay` で調整済み。
- 要素は**1つずつ順番に**出す（線 → 箱 → 結論 → 数字 → 帯）。同時にドンと出さない。
- 箱は "pop"（少し拡大しながら出現）、文字は下から少し上げてフェードイン。
- 1ページ＝**240フレーム（8秒）**。線をゆっくり描くぶん長め。

---

## 5. イラスト

- **イラストはこちら（Claude）が作る**。ユーザーには作らせない。
- 手描き風の人物はNG（"ダサい"）。**塗り＋線のフラットSVG**（`src/components/flatArt.tsx`）を使う。
- 外部の素材サイト／Canva書き出し画像は取得不可（サンドボックスでブロック）。npmパッケージ or 自作SVGで対応。
- **図解にイラスト／アイコンを積極的に足す**（文章＋図解＋イラストの三点セット）。
  - `DiagramData.art` スロット（結論の下・y940）に配置。`pop`で"出現"させる。
  - 例：「得」「正解」の結論では**グッドボタン(FlatThumbUp)** を出す。ほかチェック(FlatCheck)・
    車・コイン・銀行・グラフ・債券・天秤・矢印などを内容に合わせて。
  - 内容と関係あるものを選ぶ（飾りではなく"意味"を持たせる）。

---

## 6. 制作フロー（合意済み）

0. **【Step0：設計図で先に合意】** ユーザーは生のお題・文章を投げるだけでOK。
   Claude が (a) 何枚に分けるか判断し (b) 文字数・言い回しを図解向けに整え
   (c) **各ページに何が出るかを"テキストの設計図"（普通の日本語・1ページずつ）** で先に提示する。
   → ここでユーザーが文章で修正。画像を作る前に文章段階で固める（レンダリングの無駄を防ぐ）。
1. 固まった設計図を `SCRIPT_TEMPLATE.md` 形式 = `DiagramData` に落として連結図解リールを生成・レンダリング。
2. 動画を確認 → 修正指示 → 直す → **決定を本ファイルに追記**。
3. 次回以降は本ファイルの前提を守るので、同じ指摘は不要になる。

## 6-2. 情報不足は正直に言う（重要）

- ユーザーのお題に対し、**枚数が足りない／1枚の情報が薄い**ときは、勝手に薄いまま作らない。
- 正直に「**この内容だと情報が少ないかも／◯枚に届かないかも**」と伝え、
  補える材料（具体数字・比較・注記・締めの一文 など）を提案する。
- 3-2の「1枚≒75文字の下限」を満たせないページは、統合するか要素を足す。

---

## 7. 技術メモ（レンダリング環境）

- レンダーは chrome-headless-shell を指定＋証明書検証を回避：
  `npx remotion render <ID> out/x.mp4 --browser-executable="/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell" --ignore-certificate-errors`
- Google Fonts の TLS がサンドボックスで失敗するため `--ignore-certificate-errors` が必要。
- 出力：1080×1920（9:16）・30fps・MP4。

## 変更ログ（新しい決定はここに1行ずつ追記）

- 初版：色/ゾーン/文字サイズ/フラットイラスト/下部に文字を置かない を確定。
- ページ切替を「下から上へスライド」に統一（左右は廃止）。
- 線の描画を約2倍ゆっくりに。要素の出現タイミングを後ろ倒し。
- 結論帯（pill）の文字を 46 → 58px に拡大。1ページ 210 → 240 フレーム（8秒）に延長。
- 参考画像（産休・育休）を実測し全文字サイズを更新：見出し64・箱50・結論98・数字100・注記34・帯66。
- **締めの一文（footer）スロットを追加**（帯の下・y1360）。1枚の情報密度を参考画像レベルに。
- 見出し枠を「文字幅に合わせた自動幅＋1行」に変更（折り返し防止）。1ページ 240 → 285 フレーム（9.5秒）。
- **Step0「設計図で先に合意」**と**「情報不足は正直に言う」**を制作フローに追加。
- **改行は必ずキリのいい所で／キーワードは大きく＋色替え**を明文化（帯を2行にして債券をゴールド大に）。
- 箱にサブ文があるとき、結線がサブ文字に重ならないよう経路を変更（中央の空きを通す1本に）。
- **イラストを図解に追加**（グッドボタンFlatThumbUp／チェックFlatCheck を新設、`art`スロットで出現）。
- **線と文字の重なりを全ページ解消**：結線は文字ブロックの30px手前で止めるルールに。長すぎる結論は短くして手動改行。
